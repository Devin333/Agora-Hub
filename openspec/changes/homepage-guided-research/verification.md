# 首页研究交互验收

## 本轮实现

- 首页输入框最左侧 `+` 菜单：链接、资料、PDF、保存分组。附件与问题独立保存，分组不会自动变为参考资料。
- 自动模式和“先聊清楚”计划模式；最多两轮、每轮一个澄清问题；轻量确认可修改、选择论文/项目/两者。真实模型只生成候选，由应用校验来源、条件与限制。
- 同页研究对话、两类结果、来源链接、简短进展、停止、按来源重试、空结果和后续问题。
- 同一个历史记录保存轮次、结果、条件、附件快照、阶段与滚动位置；游客/账号隔离；刷新中断不会自动重复请求。
- 保留桌面紫色玻璃样式、右侧工作区居中的提问框和下方 2×2 模块，报告继续进入可编辑准备页。
- 论文更多结果保留关键词、近 365 天、代码和综述条件。原生阅读器链接仅由已有 compiled 且 gate 通过的正文缓存授予。

## PDF 与外部能力边界

- 上传现在先保存 `received` 身份再转换，刷新/重试复用导入身份并按账号隔离。没有通过正文质量检查时显示失败，不能以 paper ID 的存在冒充转换完成。
- 本机真实合成三页 PDF 验收通过：3 个带页码定位的章节，12932 正文字符，reading gate passed，方法/结果标记可恢复。完成后重复提交，以及模拟完成回执失败后重新解析，均保持同一 paperId，跨账号拒绝读取。
- 为带内嵌文字的 PDF 接入纯进程内 PyMuPDF 提取与现有质量门禁，无需外部解析器执行身份；不伪造 Graph identity。上传上限 50 MB，解析最多 500 页/200 万字符，默认至少 3 个非空页面章节/3000 正文字符，乱码比例不超过 2%。扫描件、加密文件、正文不足与超限均明确失败。
- 已修复 `source_type='pdf'` 错配（应为 `local`）、文档仓库误读目录条目、来源快照因账号元数据规范化而误报不可变冲突。保留真实内容变更拒绝和账号隔离。
- 私有导入文本与正式全文阅读器之间仍需独立完善转换/发布路径。当前不为仅解析文本的导入生成无法使用的 reader 链接。该边界在最终交付中必须明确。
- 论文当前来源是 2026-05-24 采集的真实缓存，共 1000 条；界面显示缓存日期。模型与 GitHub 均可能超时/限流，显示真实错误，不生成假结果。
- Google/微信/QQ、短信/邮件仍需要用户自己的外部服务配置，本次复用已有登录弹窗和身份接口。
