## 3. 产品定位与使用场景

**一句话定位：**一个围绕个人论文阅读的桌面研究助手，让用户查找、保存、阅读、理解和积累论文知识，而不必在论文库、阅读器和独立聊天窗口之间反复搬运上下文。

“Personal agent”的价值体现在论文上下文和已确认研究偏好的连续使用，不体现在代替用户操作电脑或无边界自动执行。

### 核心场景

- **发现论文：**用关键词或自然语言说明研究需求，查看有来源的真实结果，收藏到本地论文库。
- **读懂一篇：**打开真实原文，围绕全文或选中文段提问，从回答中的引用回到支撑位置。
- **保留成果：**保存摘录、笔记和有出处的分析结果，区分论文事实、用户判断和模型生成内容。
- **连续研究：**重新打开 App 恢复论文、阅读位置和笔记；经确认的本地研究偏好可在后续任务中使用或忽略。

### 最小完整闭环

提出论文需求 → 真实检索 → 收藏或导入 → 阅读原文 → 有出处的问答 → 保存笔记 → 用户确认有价值的长期记忆 → 退出并重开 → 在下一次论文任务中受控复用。

不要求每次阅读都产生记忆，也不强迫用户先聊天再打开论文。

## 5. v1 范围与优先级

### P0：首版发布条件

| ID | 能力 | 用户可见结果 |
| --- | --- | --- |
| F-01 | 桌面启动与首次使用 | 安装后从桌面入口进入独立窗口；不依赖用户打开终端、开发服务器或源码目录；能识别本机服务就绪、待配置和失败 |
| F-02 | 真实论文搜索与导入 | 明确切换“搜索本地论文库”和“在线找论文”；支持关键词/自然语言需求、arXiv/DOI/受支持论文来源输入，以及用户主动选择的本地 PDF |
| F-03 | 本地论文库 | 入库、去重、收藏、已读、基础标签/分组与排序；元数据已保存和全文已在本地是不同状态；取消收藏不等于删除论文 |
| F-04 | 原文阅读与续读 | 真实全文或明确标注的摘要；章节/页内定位、选段、阅读位置；切换论文或重开后恢复，不伪造 PDF 页码 |
| F-05 | 单论文助手 | 单篇概览、方法解释、基于证据的问答；引用可定位；显示实际任务状态及限制，不靠虚构回答模拟成功 |
| F-06 | 笔记与研究成果 | 逐篇摘录和笔记的真实保存、编辑、删除与冲突处理；复用已有合格报告保存/导出能力，支持用户主动导出 Markdown/结构化数据 |
| F-07 | 本地个人长期记忆 | 用户手动创建或确认候选后保存；可查看、修改、停用、删除、导出；召回可解释、可跳过，当前指令优先 |
| F-08 | 设置与可靠性 | 黑白主题、数据目录、模型/检索能力配置、联网范围说明、日志诊断、已有备份/恢复入口、离线本地阅读与管理 |

P0 文档基线为真实元数据、摘要和可提取文本的论文 PDF；已有解析能力可以复用，但不能将扫描件、复杂图表或数学公式的未知支持情况写成必然成功。无法处理的材料必须有明确状态和替代路径。

### P1：首版后再评审

- 多论文对照和跨论文综合问答；批量导入、书目格式交换、高级集合与统计。
- 扩展 OCR、复杂图表/公式理解等覆盖；不禁用已有合格能力，也不将增强项冒充 v1 已验收能力。
- macOS/Linux 安装分发、自动更新、托盘与后台驻留等桌面增强。

### 明确不做

新闻、项目管理、邮件、日历、购物、社交、跨应用电脑操作、任意 shell 执行、全盘扫描、无人值守研究、定时监控、自动对外发布、云端长期记忆库或跨设备同步。打开用户选择的论文文件、导出文件以及管理本 App 自己的窗口和进程，是应用基础能力，不授权 agent 操作其他应用或任意系统资源。

## 6. 信息架构与排版合同

### 桌面主体

```text
原生窗口层：拖动、最小化、最大化、关闭
┌──────────┬───────────────────┬────────────────────────────┐
│ Agora    │ 论文列表 / 搜索结果 │ 阅读工作区                  │
│ 资料库   │ 搜索、筛选、排序   │ 原文 / 概览 / 笔记 / 详情   │
│ 标签分组 │ 论文身份与状态     │ 排版正文、引用、阅读位置     │
│ 记忆设置 │                   │ 按需展开论文助手            │
└──────────┴───────────────────┴────────────────────────────┘
```

- 默认以论文阅读为中心，不增加仪表盘、大型欢迎卡片或必须先对话的聊天首页。
- 左侧延续资料库/研究主题结构，底部容纳主题切换和低频设置/记忆入口。主题或分组来自真实用户数据，不把演示中的三个主题永久当作用户已创建资料。
- 中间列表显示论文标题、作者、年份、来源和读/藏/全文状态；缺失信息明确缺失，长标题可换行，不能截掉所有辨识信息。
- 搜索框明确“本地筛选”与“在线检索”的作用，避免一次键入就意外触发远程或付费任务。在线结果使用相同列表/阅读结构。
- 阅读区“原文”和“概览”身份明确；原始 PDF 与可重排导读分别处理，不承诺把任何 PDF 直接重排成 Bear 样式。
- 助手默认收起。展开时优先保留正文宽度，可收起中间列表；窄窗口用可返回的抽屉，不把正文压成细条。助手不覆盖笔记保存状态。
- 专注模式能返回正常布局；切换主题、列表、标签或助手不丢失用户输入。

### 排版基线（建议值，视觉评审可微调）

- 正文 16–18px、行高 1.75–1.95、可重排阅读列约 640–760px；英文论文主标题 30–36px，元信息 12–13px。
- 中文正文使用可用的清晰中文字体回退；英文长标题可使用衬线体；不能依赖联网字体才能正常排版。
- 中性色双主题、轻分隔线、克制留白；状态以文字/图标辅助，不只依赖颜色。普通文字对比度目标至少 4.5:1。
- 以 1366×768、1440×900 及 125% OS 缩放验收；三栏布局建议至少 1200px 可用宽度，不足时折叠导航/列表。不设置超过 OS 可用工作区的硬性最小窗口，也不通过横向溢出隐藏内容。
- 键盘可达所有关键操作；`Ctrl+K` 到搜索、`Escape` 关闭最上层临时面板；输入法确认不误提交问题。长文编辑与模态抽屉有正确焦点行为。
- 系统原生应用图标/安装图标与此次删除的**侧栏 A 装饰图标**不是同一要求；不得误删系统窗口关闭控件。

## 7. 关键用户流程

### 7.1 首次启动与重开

1. 安装构建具备运行所需的被管理依赖或明确的引导安装路径；首次启动不要求用户克隆仓库。
2. 创建或安全选用本地资料位置，显示路径与联网边界；存在旧资料时不得覆盖或悄悄创建第二份 owner。
3. 复用现有本地身份/会话，首次初始化、登录和错误由真实服务判断；不因运行在 App 中就跳过私有资料授权。
4. 无资料时显示空库和“找论文 / 导入 PDF”入口，不注入六篇演示论文。缺模型不阻止可用的本地阅读和笔记能力。
5. 重开后恢复同一 owner 的最近论文、阅读位置和已保存笔记。非终态任务先核对，不能自动重放可能收费的请求。

### 7.2 检索 → 入库 → 获取全文

1. 用户明确发起在线检索，显示实际执行的条件和阶段；复用既有工具，由受控 workflow 执行。
2. 区分检索成功有结果、成功零结果、部分来源失败和整体失败，不拿缓存或示例填充失败结果。
3. 使用服务端稳定论文身份、规范来源 ID 或内容身份判重；不凭相似标题无提示合并不同版本。
4. 入库以持久化 receipt 为准；收藏元数据后，全文状态独立为未获取、处理中、可阅读或失败。
5. 无权获取、网络失败或不支持的文档提供来源页/本地导入路径；不绕过访问限制。
6. 导入文件需用户选择，校验格式和大小；将 PDF 绑定已有论文时确认身份。不扫描用户其他目录。

### 7.3 阅读 → 问答 → 引用

1. 打开材料时显示证据范围：全文、部分解析、摘要或仅元数据。
2. 用户可针对当前论文或选段提问；建议问题只预填，发送是单独、明确的动作。
3. 展示真实请求/运行阶段、超时或失败；暂态内容若流式显示必须标记为未完成，不能提前变成最终合格成果。
4. 关键事实应带论文、文档修订、页/章节/段落锚点及支撑片段。点击能定位支撑内容，不以只打开论文首页算完成。
5. 只有摘要时回答须限定为“基于摘要”；证据不足或 locator 不再有效时明确说明，不伪造引用或旧位置。
6. 用户可保存合格成果为笔记或既有报告，并查看其来源；普通助手回答不能绕过 report quality gate 或 publication 权限。

### 7.4 笔记 → 记忆 → 后续复用

1. 笔记围绕 paperId 和原文位置，显示保存中/已保存/失败；后台确认之前不冒称已保存。
2. 用户明确选择一条偏好或研究背景作为记忆，或在用户主动要求整理记忆时检查系统提出的候选；候选须显示内容、来源、作用范围并允许修改/拒绝。
3. 普通笔记、论文观点和原文中的指令不自动变成个人偏好；所有未确认候选都不参与个性化召回。
4. 记忆保存到本机 owner namespace。用户能编辑、停用、删除和导出；记忆不是只在这一窗口活着的 UI 状态。
5. 后续任务展示“本次使用的记忆”，在发起外部调用前可选择不用；当前明确指令优先于历史偏好。
6. 停用/删除后后续请求不再使用该记忆及其派生索引；已发送请求不能被追溯撤回，需如实说明。不得从残留笔记无确认地重新生成已删除记忆。

## 8. 数据、记忆与联网边界

### 数据归属

| 逻辑数据 | 归属与持久化要求 |
| --- | --- |
| 论文元数据、收藏、阅读状态、标签/分组 | 当前本地用户的正式 workspace/catalog owner；版本冲突可见 |
| PDF / 解析产物 / 证据片段 | 受控本地资料或 artifact root，保留来源、修订和 digest；缓存与唯一原件分开 |
| 笔记、选段、会话与分析成果 | 复用现有工作区/阅读/报告模型，关联 paper、owner、source、run；不同论文和用户不可串用 |
| 个人长期记忆及派生索引 | 只在用户电脑持久化；通过 application service 控制，不能写入渲染层 `localStorage` 充当唯一事实源 |
| 配置与密钥 | 主题等偏好可本地持久化；provider 密钥放服务端或 OS 安全存储，不暴露给普通渲染页面，不进入诊断日志和默认导出 |

上述是产品逻辑分类，不要求建立同名的第二套数据库。正式模型与已有 owner 先做映射；仅缺失的合同才新增。用户能在设置中查看实际数据位置。

### 个人记忆最小信息

稳定 ID、owner/namespace、内容、类别、来源引用、状态（候选/启用/停用/删除标记）、创建/修改时间、revision。候选与活动记录隔离；编辑和删除更新派生召回索引，不能遗留可被继续使用的旧版本。删除原笔记时提示相关记忆的归属，不能让来源消失后仍声称能回到原始证据。

用户手动保存由确定性 application service 授权、校验和持久化；LLM 只能提出候选。需要模型的流程由 Harness 执行有界 `PLAN -> EXECUTE -> VERIFY`，质量门失败受控重试/停止，并记录 durable transcript。LLM 不决定记忆写入、工具授权、质量通过或发布。

### 本地存储不等于零外发

- 联网检索会发送用户主动提交的检索词；远程推理可能发送选中的论文片段、问题和用户允许的记忆片段。
- 首次配置应说明目的地、数据类别与用途；使用记忆前需有明确启用的策略并能按次关闭。不默认上传整库，不新增云端长期记忆同步。
- Embedding 同样遵守该策略：索引落地本机不代表远程 embedding 不会看到文本。未获许可时不能发送个人记忆，可使用本机可用的检索方式。
- 不宣称提供商零留存或端到端加密，除非真实方案与证据支持。离线/禁止外发状态下不得偷偷切到远程服务。
- 论文和检索内容按不可信资料处理，其中的“执行命令/忽略规则”等文字不能改变工具权限或诱导写入个人记忆。

### 删除、备份和恢复

- 删除活动记忆清除后续召回路径，历史对话或用户导出的副本不自动改写；UI 明示二者区别。
- 备份包含已登记的本地 owner、记忆及必要索引信息，默认不含 provider 密钥；只清缓存不删除原始笔记和资料。
- 复用既有隔离验证/激活/恢复代际流程。恢复旧备份可能带回旧记忆，必须预览并确认，不能后台悄悄复活删除条目。
- 升级、卸载保留个人资料；“删除全部数据”是独立且明确确认的操作。原地不兼容降级必须拒绝。

## 9. 状态、失败与离线

| 场景 | 必须呈现的行为 |
| --- | --- |
| 服务启动中 / 待配置 / 故障 | 明确区分，提供诊断/重试入口；配置存在不等于连接或能力验证通过 |
| 检索零结果 / 检索失败 | 分别提示，无假论文、无无限 loading；保留用户查询 |
| 全文不可得 / 部分解析 | 仍可查看已获得元数据或原文文件，说明问答范围，不冒充全文可用 |
| 模型超时 / 网络中断 | 保留问题与已保存成果；使用 request 身份先查实际状态，不盲目重复付费执行 |
| 停止 / 取消 | 只有后端确认后才显示已取消；不支持终止时明确只是停止等待或关闭面板，运行可能仍在继续 |
| 保存冲突 / 磁盘不足 | 保留编辑草稿，明确未保存，不静默覆盖另一版本或报告成功 |
| 离线 | 已在本地的论文、历史结果、笔记、记忆管理可用；在线检索/新远程问答明确不可用，不自动补发队列 |
| 关闭窗口 / 异常退出 | 正常退出提示未保存编辑和活动任务；复用安全 drain/恢复合同，只管理本 App 拥有的进程，不杀其他 3000/8000 服务 |

## 10. 桌面交付与安全要求

- v1 提供可追溯的 Windows 安装构建、独立窗口与桌面入口；本机浏览器预览、`.lnk` 打开网站或 `npm run dev` 不等同于此交付。
- 运行依赖、首次安装条件和可选解析组件明确列出。无模型配置应可启动本地工作区，但真实问答仍须用合格 provider 完成发布验收，不能以“待配置”代替成功测试。
- 使用既有运行管理器作为唯一生命周期 owner；重复启动复用或聚焦同一实例，不能争抢端口、接管无关服务或启动两份 writer。
- 桌面渲染层不能获得任意文件/进程权限。必要桥接使用窄接口、来源校验和参数验证；用户选文件不等于授权全盘访问。
- 本机 API 保持 loopback、身份和 owner 校验，并验证 Origin/Host 等信任边界；“只在本机”不是移除鉴权的理由。
- 外链打开受校验的外部目标，不允许任意协议/命令或把不可信远程页面加载进有宿主权限的窗口。
- 默认不自启、不自动付费调用、不自动下载大模型；升级不丢资料。首版不承诺无证据的签名信誉或免安全提示，实际签名状态如实交付。

## 11. 可验收标准

验收必须绑定同一源码、构建、配置与依赖身份。测试 fixture 可覆盖故障，但不代替至少一次真实检索、真实 PDF、合格模型的桌面闭环。所有条目当前均未核销。

| ID | 通过条件 | 证据 |
| --- | --- | --- |
| AC-01 | 在约定 Windows 环境安装并通过桌面入口进入独立窗口，不依赖开发终端；重复启动不产生第二个 writer | 安装/运行记录、构建身份与进程归属 |
| AC-02 | 黑白主题均仅保留侧栏 `Agora`，A 图标和副标题不存在且无占位空洞；其他既定主体结构保留 | 对照用户截图的实际 App 截图 |
| AC-03 | 真实空库无六篇样本；首次身份/资料目录/待配置状态真实，未授权无法访问他人数据 | 首次启动与鉴权测试 |
| AC-04 | 本地筛选不触发外网；真实在线检索可回溯来源，零结果与工具失败有不同状态 | 请求记录与真实来源 |
| AC-05 | 保存同一已识别论文不重复；元数据、收藏、下载状态不混淆；导入真实 PDF 后重开仍可离线打开 | paperId/source/digest 与重启记录 |
| AC-06 | 全文、摘要、部分解析分别正确标识；可用材料有真实定位和阅读位置恢复，缺失全文不被当作已读全文 | 三类材料验收记录 |
| AC-07 | 合格模型完成真实问答，关键事实有支撑片段；点击引用定位到正确修订和位置；无证据问题不编造引用 | request/run/quality 记录与定位操作 |
| AC-08 | 笔记和合格成果真实保存、编辑、导出；冲突或磁盘写入失败不报告成功、不清空输入 | 持久化回读与失败测试 |
| AC-09 | 普通笔记不自动成为记忆；未确认候选不参与召回；确认后的记忆和本机索引可在重开后读取 | owner 数据与重启回读 |
| AC-10 | 可编辑、停用、删除和导出记忆；后续请求不使用停用/删除条目，重启/重建索引后仍成立 | 生命周期与召回测试 |
| AC-11 | 后续任务显示实际使用的记忆，当前指令和“本次不使用”能覆盖旧偏好；拒绝远程记忆使用时无相关外发 | 任务上下文与网络断言 |
| AC-12 | 离线仍可读本地全文、笔记和历史答案并编辑本地数据；无缓存内容或远程能力明确不可用，不自动补发 | 断网验收 |
| AC-13 | 超时、断连和重开通过 request 身份核对；没有后端确认不显示取消/成功，不重复付费执行 | 受控失败与恢复证据 |
| AC-14 | 在本机隔离目标验证备份恢复，原资料不被破坏；恢复旧记忆、会话和非终态任务遵守确认与代际合同 | backup manifest、checksum、恢复记录 |
| AC-15 | 约定分辨率、125% 缩放、双主题下无关键遮挡/文档横溢；键盘、抽屉焦点、输入法和长文排版可用 | 实际 App 截图和交互检查 |
| AC-16 | 正式 App 不加载 lab fixture，不暴露危险宿主接口；来源内容不能授权工具或写记忆；代码范围检查、strict spec、完整 smoke 通过 | 依赖边界、安全测试与 gate 记录 |

“重开 App”与“用户重启电脑”分别记录。本变更不得用 App 重开代替 `research-local-desktop-readiness` 中尚未完成的真实电脑重启验收，也不在未经用户要求时操作系统重启。

## 13. 待确认但不阻塞本稿的假设

1. **平台与分发：**先按 Windows x64 单设备考虑；跨平台、最终包名、签名和更新策略不在本稿假装已定。桌面宿主在 M1 做小范围验证后用 ADR 冻结，当前不凭体积/性能印象选框架。
2. **联网与费用：**优先沿用用户已有合格 provider 和搜索配置；不假定免费内置模型或自动花费。真实验收的来源、模型、调用次数/费用上限先确认，再执行。
3. **文档与记忆：**v1 以单篇、可提取文本 PDF 和用户确认记忆为必交付；复杂版面增强和无人值守的后台记忆归纳需要另行评审。用户若希望纯离线推理，应单独核定硬件与模型范围，不能由“记忆在本地”推导出来。
