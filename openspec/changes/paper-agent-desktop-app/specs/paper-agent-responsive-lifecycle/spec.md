## ADDED Requirements

### Requirement: 启动中关闭必须使用协作取消
桌面宿主 MUST 在启动操作尚未完成时通过受控、私有、有界的取消通道请求取消；取消检查 MUST 覆盖完整文件验证、复制和服务启动阶段。取消确认不等同于 runtime 已停止；宿主 MUST 再执行停止与归属核对后才能报告退出完成。不得为响应取消绕过完整校验或遗留半发布的 active release。

#### Scenario: 完整校验时用户请求关闭
- **WHEN** 尚未进入真实工作区的启动操作正在执行且用户请求关闭
- **THEN** 宿主请求协作取消，不等待整个启动超时结束才开始处理关闭
- **AND** runtime 在安全检查点终止后续启动，清理本次拥有的资源，并提供可核对的最终状态

#### Scenario: 取消不能证明已停止
- **WHEN** 取消被接收但服务或其归属仍无法核实
- **THEN** 宿主保持失败或未知反馈而不是伪报停止成功
- **AND** 重复关闭请求复用同一个受控收尾操作，不并发创建第二组服务

### Requirement: 已拥有进程收敛必须共享有界退出预算
runtime MUST 在业务 admission 关闭且 drain 成功后只收敛身份已核实的本实例服务。Windows 无控制台后台进程 MUST NOT 使用可能无效或广播到其他进程的 console control 信号。服务停止与日志收尾 MUST 使用共享有界预算，日志采集器应在生产者结束后通过 EOF 完成必要的 flush，而非为每个进程串行等待完整宽限期。

#### Scenario: 空闲 Windows 服务正常退出
- **WHEN** 无活动业务租约且本实例进程身份均可核实
- **THEN** drain 可立即完成，runtime 按已核实身份收敛服务并等待日志自然结束
- **AND** 停止耗时不因服务和日志进程数量线性叠加完整超时

#### Scenario: 归属不明或业务未能 drain
- **WHEN** 发现 foreign process、进程身份复用、端口仍被占用或活动业务未能在预算内完成
- **THEN** runtime 返回有界且明确的失败或未知状态
- **AND** 不按进程名结束进程，不把仍在进行的业务伪报为已安全完成

### Requirement: 退出保护与协议完整性不可退化
桌面宿主 MUST 保留未保存内容、活动任务和无法核实状态下的原生确认与失败保护。CLI stdout MUST 保持单个有界 JSON 响应；协议污染或超时 MUST 保持可诊断的未知或失败结果，不得通过截取最后一行或忽略错误伪报成功。

#### Scenario: 收尾期间窗口提供反馈
- **WHEN** 用户已确认退出且 runtime 正在停止
- **THEN** 窗口提供明确的收尾反馈并禁止重复发起互相冲突的生命周期操作
- **AND** 只有在停止核实成功后才完成窗口退出

#### Scenario: 协议响应不可解析
- **WHEN** 收到额外 stdout、无效 JSON、超界响应或不能核实的退出结果
- **THEN** 宿主记录脱敏后的协议错误并保留安全反馈
- **AND** 不将取消请求送达、子进程消失或窗口消失单独当作业务安全停止的证明

### Requirement: 修复必须绑定隔离候选与实测证据
启动、停止和打包修复 MUST 在全部相关实现与回归用例完成后，针对精确冻结的候选统一检查。最终提交 MUST 仅包含本次归属路径，保留并行未提交工作；安装与性能结论 MUST 区分已构建、已安装、真实工作区 readiness 与完整生命周期实测，不得重复使用旧版本通过结果代替新候选验收。

#### Scenario: 新候选交付
- **WHEN** 准备交付包含生命周期修复的 Windows 候选
- **THEN** 记录源码、检查、安装产物、运行依赖和实测起止时间的关联
- **AND** 运行匹配的回归、OpenSpec strict 和必需完整 smoke，失败须根因修复后重新核对
