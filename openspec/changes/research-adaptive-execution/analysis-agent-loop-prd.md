## 1. 一句话概述

让实验分析 worker 在证据充分时直接提交候选，在证据不足但可补足时按需读取当前论文材料、利用工具观察继续分析，并由 Harness 统一控制授权、预算、验收、局部修复、恢复与最终发布。

**不训练专用小模型，不要求使用者额外部署 checkpoint；复用已配置并通过资格检查的模型后端。多轮是完成任务的手段，不是必须执行的固定轮数。**

### 1.1 用户与产品价值

- **论文阅读者 / 研究者：**希望实验结论、数据、比较条件与原文对应，不需要理解 AgentLoop、TaskPlan 或 worker 调度。
- **自部署使用者：**希望沿用现有模型配置，不因启用多轮分析而增加一个强制常驻模型服务。
- **项目维护者：**需要定位错误来自材料缺失、模型候选、工具执行还是业务验收，并能解释成本与停止原因。

成功体验不是“系统多调用了几次模型”，而是“需要核对时确实读取了材料，形成可追溯的候选；无法确认时清楚说明缺口，而不是猜出一个完整答案”。

## 3. 目标与非目标

### 3.1 首版必须实现

1. **真实动作闭环：**模型可以在一个已接纳的实验分析目标内提出工具调用或最终候选；工具真实执行结果进入后续模型请求。
2. **合法证据闭环：**候选引用可追溯到当前论文、源修订和已接纳证据，不由模型自行创造合法引用。
3. **受控完成：**局部输出校验、Harness VERIFY 和顶层发布分别执行；任何一层成功都不能冒充整个 run 完成。
4. **有界成本：**模型、工具、传输重试、局部修复和恢复后的执行均受同一请求预算血缘约束。
5. **可恢复与可解释：**通过已有持久事件和 receipts 复原执行事实，展示业务进度、资源与停止原因。
6. **可证明收益：**相同材料、模型和质量标准下，比较一次候选生成与按需多轮的质量、完整失败率、成本和延迟。

### 3.2 首版不做

- 不训练 router、工具选择小模型或复杂度分类器，不要求新的模型权重部署。
- 不新增 planner 调用，不因为一次补读而启动 TaskPlan、额外 fan-out 或递归子 agent；原图中的其他分析角色保留。
- 不重写来源收集、文档解析、RAG、Reader、质量 gate 或发布系统；局部证据适配遵循既有 owner 边界。
- 不开放任意网页、跨论文搜索、shell、任意文件访问、发布工具、直接 memory 写入或 active skill 修改。
- 不把每次阅读、改写或模型思考变成独立 Graph 节点，不新增调度器、预算账本或事件存储。
- 不承诺确定性 gate 能证明所有学术语义正确，不以模型自评取代独立语义评测。
- 不在本专项中提前切换整个公共 API 的模式字段合同；该切换仍由总体变更统一实施和发布。

## 4. 用户场景与可见结果

| 场景 | 预期产品行为 | 成功 / 停止依据 |
| --- | --- | --- |
| 已有证据覆盖实验指标和比较条件 | 首轮允许直接提交候选，不强制读取工具或再问一次模型 | 相同业务合同和 gate 通过；无额外 planner |
| 结论依赖实验表，但初始上下文只含摘要 | 按授权读取相关原文或已解析表格，回填结果后继续分析 | 引用经过接纳，指标与比较条件完整，并通过既有质量门 |
| 表格与正文说法存在差异 | 保留证据来源与差异，提交带限制说明的候选；不足以支持的断言不得当作已验证事实 | 按质量 profile 决定允许披露限制还是必须停止，不能自行降低标准 |
| 材料缺页、表格未解析或授权材料中找不到答案 | 只在已注册能力和预算内尝试补足，失败后展示具体缺口 | 不伪造工具结果，不通过增加轮次冒充缺失的解析能力 |
| 模型申请未授权材料或工具 | 运行时拒绝，记录原因，停止相应分析执行 | 不换接口、换层级、换 agent 或扩大 allowlist 绕过 |
| 预算耗尽、重复无进展、用户取消 | 停止新派发，保存已发生的事实和资源消耗 | 不伪造成功，不触发正式发布 |
| 执行中断后恢复 | 沿原冻结合同核对 receipts、预算和 pending 状态后继续或明确停止 | 不重新分类任务、不重置预算、不盲目重发未知操作 |

用户看到“正在分析实验”“正在补充证据”“正在核验”“证据不足”“已取消”等业务状态，不需要选择静态/动态、AgentLoop、planner 或 agent 数量。这些是现有状态的界面投影要求，不是新建一套 run lifecycle 枚举。

## 5. 执行模型与职责边界

```text
既有来源、文档与证据阶段
            ↓
Harness 准入并派发实验分析任务
            ↓
Graph-bound 实验分析 worker
    ├─ 组装目标、合法 refs、工具描述、观察和反馈
    ├─ 模型提出局部动作候选
    │     ├─ tool_call → 授权 / 预算 / 参数检查
    │     │                 ↓
    │     │           真实只读工具执行
    │     │                 ↓
    │     │       observation / 证据接纳事实
    │     │                 └─────────→ 后续轮次
    │     └─ final_output → 局部输出校验
    └─ 输出适配回既有实验分析合同
            ↓
Harness VERIFY
    ├─ 通过 → 保留既有其他角色与后续主链
    ├─ 可修复且有预算 → 声明范围内局部 repair / replan
    └─ 硬失败、无进展、预算耗尽 → 停止
            ↓
顶层必需输出、质量 gate 与 publication authority 合格后才发布
```

| 层次 | 拥有的职责 | 不得承担的职责 |
| --- | --- | --- |
| Research application / domain | 实验分析目标、证据业务规则、候选适配、缺口与失败分类 | 绕过 Harness 直接改全局路由、额度、正式产物或 active skill |
| Harness | Graph 和执行身份、准入、预算、VERIFY、repair、恢复、发布控制 | 将模型 confidence 或自由文本当作质量判定 |
| AgentLoop / 模型 | 当前目标内的动作候选、受控工具交互、实验结论候选 | 决定全局下一节点、扩大权限、修改正式 memory、直接发布 |
| ToolRuntime 与业务工具 service | 授权、参数、资源和执行约束；返回真实材料和执行事实 | 让文档内容、工具输出或模型参数覆写控制策略 |
| Composition / infrastructure | 注入真实模型、工具、持久化与运行资源 | 将论文业务规则迁移进通用框架，或让业务层反向依赖 interfaces/infrastructure |

“保留主图”指保留既有粗粒度业务阶段与必需输出，不表示可以原地修改已冻结 Graph。新增 binding 或 repair 边界应形成适用的新版本准入合同；已开始的 run 保持原 identity。

## 6. 功能需求

### AL-FR-01 任务准入与低开销入口

- 首版仅准入单论文实验分析，冻结论文/源修订、目标、输入 refs、质量 profile、允许工具、模型与 worker bindings、预算和允许的修复边界。
- 已知结构化分析目标由普通函数规范化，不额外调用复杂度模型或 planner。是否准入该 worker 由服务端已发布 profile 决定，不由用户或模型直接指定。
- 结构、贡献等既有必需角色和后续输出不得被省略；实验分析成功不替代其他角色验收。
- 已知需要补读时允许直接进入合格 loop，不要求先完整跑失败一次；证据充分时允许首轮直接提交。
- 模型、工具、输入质量或持久化资格不满足时，在派发前明确拒绝该能力，不以空工具、假结果或静默质量降级代替。

### AL-FR-02 真实模型动作协议

- 每轮传递当前任务、受授权的输入与证据、可用工具 schema、已接纳的工具观察、必要失败反馈和剩余资源限制。
- 替换仅包装旧候选结果的接法，复用现有真实 LLM client / route；最终透传真实 usage、错误、执行身份及关联 receipt。
- 首版正常动作集合限定为 `tool_call` 与 `final_output`。未支持动作由确定性协议校验拒绝，不自动解释为全局控制指令。
- 明确选择并验收动作适配方式：兼容现有结构化动作协议；若使用 provider 原生 `tool_calls`，必须显式适配并覆盖真实 client 契约测试，不能假定 SDK 返回值已被循环消费。
- 中间动作协议与最终业务 schema 分离。最终实验输出 schema 不得让每一轮只能返回终态对象；最终校验也不得因允许中间动作而被移除。
- 本专项不增加子委派、memory 写入或 skill 演进权限；输入中的指令性文本只作为不可信材料，不成为控制策略。

### AL-FR-03 真实、只读且有范围的证据工具

- 优先接通已声明的 `retrieval.read_source`，复用真实文档、证据和检索 service。已有名称、allowlist 或 schema 不等于工具实现已经注册。
- 工具只读取当前任务授权的论文和源修订；指定论文之外、任意 URL 或任意文件路径不属于首版能力。
- 返回原文或实际解析结果，以及可核验的来源、修订、位置、内容校验信息和结果引用；这些字段由 service / runtime 提供，不由模型自签。
- 单次返回量和累计上下文量受 profile 限制；较大结果沿用现有受控 artifact/ref 机制，不通过无上限文本回填规避 token 预算。
- 图片、表格、页面未被现有材料链实际提供时，返回明确的不可用事实；不得伪造已读取表格或顺便新增未验收解析能力。
- 真实授权、execution profile、参数、超时、取消、预算和工具结果校验在运行时完成，不能仅依靠 prompt。

### AL-FR-04 补充证据的接纳与版本

- 读取已有已接纳证据时保留其 identity 和血缘；新增片段必须先通过既有证据/ref authority 的校验和持久接纳，才成为候选的合法引用。
- 新证据限定于同论文、同源修订、已授权材料。新增证据 ID 不等于扩大权限；禁止由模型直接追加 allowlist 或自行宣布 ref 已被接纳。
- 工具执行成功、原始 observation 已记录、证据可被引用，是不同事实。接纳失败或结果不明时，不得把该片段用于已验证断言。
- 新证据形成可追溯的新版本或派生 refs，保留旧 evidence pack；不得原地改写已接纳输入以让旧候选看起来继续有效。
- 补证后根据依赖重新验证受影响结果；未受影响且仍有效的已接纳结果可以复用。正式 source revision 改变须重新准入，不能冒充同一次补读。
- 如既有 authority 不能表达所需补证接纳，先在原责任边界补合同并验收；不创建独立“允许引用列表”绕过现有 gate。

### AL-FR-05 实验候选与三级验收

- 最终输出适配回现有实验分析合同，保留所需 claims、scores、证据与来源血缘；新增字段需要版本化合同，不随意改变下游消费者。
- 对实际存在的实验结果，候选应保留指标值、单位/方向、数据集或评测集、比较对象、实验设置及限制；缺失信息必须显式表达，不能补造数值和比较条件。
- **局部输出校验：**动作和结构是否合法、必需字段是否完整、当前任务约束是否满足；可修复失败产生有限反馈。
- **Harness VERIFY：**按已声明 gate 检查身份、引用资格、业务约束、输入输出血缘和质量要求；不得由模型自评替代。
- **顶层交付验收：**既有全部必需角色、整体质量与 publication authority 仍须合格。loop 成功、工具成功和局部 gate 通过均不等于 run 已完成。
- 引用存在和 schema 正确不证明学术语义正确；独立语义评测必须另外验证错值、错引、比较条件不一致和无据断言。

### AL-FR-06 失败反馈与有界修复

反馈应关联真实 observation/gate ref，包含原因码、目标候选/claim、相关输入修订、缺口、允许修复范围和剩余资源。字段是逻辑需求，沿用或扩展既有合同，不新建竞争性的状态对象。

| 失败类型 | 允许行为 | 禁止行为 / 终止条件 |
| --- | --- | --- |
| 普通模型动作解析错误、候选字段缺失 | 在 loop 的解析/输出修复上限内反馈并重试 | 不能将输出格式修复解释为授权或 execution identity 修复 |
| 当前合法证据需要进一步定位或核对 | 提出只读动作，运行时检查后执行；观察回填 | 不能擅自扩展到其他论文或源修订 |
| 业务 gate 确认的可修复缺证 | Harness 根据已接纳事实，在声明 repair 边界内补证并重跑受影响分析 | 模型自由文本不得直接决定路由；不得整条主链无条件重跑 |
| 同一失败反复出现且无新事实 | 记录无进展并停止 | 改写 prompt、换个动作 ID 或重复同一查询不算新证据 |
| 短暂、可恢复的服务故障 | 由既有执行层执行受预算限制的 transport/tool retry | 不能自动启动 planner、扩大权限或将未知执行当作未消费 |
| 权限拒绝、身份/来源修订损坏、能力不支持、取消 | 失败封闭，停止相应执行并交回 Harness | 不能换工具、换路径、换 agent 继续绕过 |
| 总预算、时限或修复上限耗尽 | 停止新派发，按事实展示未完成及原因 | 不重置账本，不发布伪完整结论 |

失败指纹至少包含目标、gate/失败类别、输入修订和已尝试修复类别。只有新接纳证据或新的有效执行事实才可以支持进一步修复；同一故障无事实变化不得重复升级。

### AL-FR-07 共享预算与停止规则

- 复用请求级权威预算账本及 reservation/receipt。内层循环、外层 repair、底层传输重试、其他分析分支和恢复均归属同一请求血缘。
- 派发前原子预留，按真实 receipt 结算；未知结果按既有规则保守占用或核对。禁止内层预算独立于父级无限增长。
- 对模型轮次、实际模型调用、工具执行与重试、token、wall-clock、worker attempts、`max_replans` 分别设有限上限，并取父级剩余预算与任务 profile 的更紧约束。
- M0 阶段必须为首个 pilot 冻结版本化任务 profile，明确每次执行的局部上限和跨该实验任务重入/repair 的累计上限；局部 attempt 可以重新分配剩余预算，但不能清零累计消费。本文不在模型和任务分布未确定时虚构统一最优额度，也不将现有某个 SubAgentSpec 的数值当作全局默认。
- provider 重试是额外实际调用，不能藏在“一个 turn”内不计费。实际调用/token/时限/成本阈值必须由受审查的版本化 model/task profile 明确给出；缺少可执行限制时不得启用该 profile。
- 如果 policy 要求预留最终输出机会，应在分配工具动作前保留相应预算；预留不保证最终成功，也不授权突破总额。
- 重复动作、连续工具失败和无进展检测复用既有能力；终止必须带原因。扩大预算需要原有显式授权及 revision，普通反馈和恢复不自动续额。

### AL-FR-08 持久记录、恢复与并发隔离

- 使用既有 canonical event/transcript 记录任务准入、Graph/worker/model/policy/quality identity、轮次、结构化动作、预留、执行 receipt、观察与证据接纳、候选、gate 及停止原因。
- 每次 Harness phase transition 和相关准入决定在既有责任边界持久化。数据可通过 refs 关联，不要求复制完整原文、私有上下文或内部思考。
- Graph-bound 工具、模型调用和候选保持 execution identity；同一模型后端可以复用，但可变上下文、工具结果、预算与授权不得在论文、run 或并行分支之间混用。
- 区分**回放**与**继续执行**：回放根据已记录事实还原决定，不重新请求模型；恢复后的新执行必须遵循原冻结合同和剩余预算。
- 已知完成且有有效 receipt 的操作不得重复消费或提交；状态未知时先核对。仅当操作被明确认定为可安全重试且符合预算/幂等策略时才能重发，不能凭空保证外部调用 exactly-once。
- 旧模型/工具/binding 版本不可恢复时明确停止或进入既有隔离处理，不静默使用新版本。取消后不派发新动作，迟到结果按既有资格规则处理。

### AL-FR-09 用户反馈与诚实交付

- 复用现有进度投影，显示正在核对的业务事项、补证原因、主要缺口、资源消耗与停止原因；不展示内部推理、凭据或未授权材料。
- `final_output` 只表示候选已提交。只有顶层结果和发布资格合格，才展示整个分析已完成。
- 证据不足、预算耗尽与服务不可用须区分，不统一显示“分析完成”或“未知错误”。
- 如质量 profile 明确允许带限制的交付，必须披露未核实项且不得把它们标为已验证结论；否则保留候选/诊断并以未完成结束。
- 保留现有取消和必要授权入口，不新增要求用户选择执行引擎的开关。

### AL-FR-10 部署与发布边界

- 复用已配置模型服务；首版不附带新 checkpoint，也不要求使用者部署额外模型。工具只接现有受支持材料能力。
- 为模型动作协议、工具执行、证据接纳、预算和质量建立可审计的资格记录；模型路由或 fallback 只能来自已冻结且验收合格的集合，不能临时换模型继续。
- 不因静态/loop/TaskPlan 的选择改变 quality profile；现有输入质量与动态选项的耦合如影响本路径，须由所属任务解除并验收后才可发布。
- 仅对新准入启用或回滚版本化绑定；活动 run 按原合同完成、取消或停止。回滚不得删除活动 run 的恢复依赖或降低质量门。
- 本专项的离线测试、局部评测和小范围内部资格，不等于总体自适应 release 合格；不得借本文件打开尚未通过父级发布门的生产默认。

## 8. 验收标准

优先级均为首版 P0；下列项目不能因为只做实验分析而删除。`AL-AC` 是专项验收编号，不改写父级 AC 编号。

| 编号 | 场景与可检查结果 | 验证方式 |
| --- | --- | --- |
| AL-AC-01 | 材料充分的标准任务可首轮提交；无额外分类/planner/fan-out，其他必需角色仍执行 | 离线接线与调用计数测试 |
| AL-AC-02 | 脚本化 `tool_call → observation → final_output` 实际经过生产 application、Graph-bound worker、真实工具 adapter 和业务 gate；观察进入下一轮输入 | fake 模型 + 真实业务路径 + 授权材料 fixture |
| AL-AC-03 | 正式模型 client 的动作协议、usage、执行身份和错误透传符合合同；不是固定包装 `final_output` | client 契约测试；另有受控真实模型验证 |
| AL-AC-04 | 未授权工具/论文/修订、伪造身份、材料内指令无法获得执行权限；拒绝后不通过另一接口继续 | 权限、输入注入与执行 profile 测试 |
| AL-AC-05 | 新片段未接纳时引用被拒；接纳后可回溯原文和 revision；旧 evidence pack 未被原地覆盖 | 证据 authority、gate 与血缘集成测试 |
| AL-AC-06 | 补证后仅重算/再验证受影响结果；仍有效的来源、编译和其他结果可复用；陈旧候选不能继续发布 | 依赖与失效测试 |
| AL-AC-07 | 解析/结构错误可有限修复；业务缺证只能经 gate 事实走声明 repair；无新事实的相同失败停止 | 反馈、指纹与 state-machine 测试 |
| AL-AC-08 | 权限拒绝、身份损坏、取消、能力不支持、预算耗尽不被升级为更多 agent 或更宽权限 | 失败分类与后续零派发断言 |
| AL-AC-09 | 内循环、外 repair、传输重试、并行分支合计不超过请求限额；重入与恢复不归零；未知调用不被免除计费 | 预算边界、竞争与故障注入 |
| AL-AC-10 | 动作预留前后、工具返回/receipt 前后、证据接纳前后、gate 与发布前后的中断均有正确恢复或停止结果 | crash、重复/乱序事件与幂等测试 |
| AL-AC-11 | 并行论文/分支及顺序复用同一模型后端时，输入、工具结果、授权和候选不存在串用 | 隔离与并发集成测试 |
| AL-AC-12 | loop 成功但业务 gate 失败不得显示总体完成或正式发布；限制性交付遵循同一 quality profile | 应用、状态投影与发布断言 |
| AL-AC-13 | 错值、错引、错误比较条件和无据结论不因格式合法而在独立评测中算正确；真实补读收益与全部失败被统计 | 独立语义 rubric 的受控真实模型评测 |
| AL-AC-14 | 模型/工具/质量依赖缺失时在准入阶段明确不可用；回滚只影响新准入，旧 run 恢复 identity 不变 | 资格、配置与回滚演练 |
| AL-AC-15 | 不要求额外 checkpoint/model service；既有模型配置及材料 service 足以运行通过资格检查的 profile | 部署 smoke 与依赖清单核查 |
| AL-AC-16 | 所有验收有需求—实现—测试/运行证据映射；仅有 fake 成功或局部两组结果不得宣布总体 release 合格 | 发布证据与文档审查 |

fake 测试允许验证控制合同，不证明真实模型理解、工具选择质量或学术准确性。真实模型实验必须另行取得资源授权，不因本 PRD 的提交自动执行。

## 9. 评测、成功指标与发布判定

### 9.1 两个不同层次的评测

1. **专项接线与消融评测：**比较原一次候选生成与本受控多轮 worker，判断实验分析闭环是否真正带来收益；不新增动态 planner。
2. **总体产品发布评测：**仍须满足父 PRD 第 9 节的固定 / 始终规划 / 自适应三组比较、独立语义判定及发布门。两组专项结果不能替代第三组，也不能将专项评测通过描述为自适应系统已经发布。

不同组使用相同原始材料、source revision、模型/价格版本、quality profile、授权范围和请求总预算。允许的工具访问材料与补读范围事先冻结，新增检索和补证的开销全部计入，不给实验组额外的隐藏材料或额度。

### 9.2 数据与统计要求

- 数据覆盖材料充分、需定位实验段落/表格、比较条件复杂、正文与表格差异、材料不可用和无法支持结论等任务；控制性故障由独立离线矩阵覆盖。
- 按论文或任务族隔离 pilot 与正式留出集，禁止同一论文的近重复样例跨集泄漏。
- pilot 用于确定 profile、样本量、方差、配对重复次数和统计方法；正式留出前冻结，不用留出结果反向调 prompt、预算或阈值。
- 使用独立参考材料与 rubric，评测者不以被测模型的自评作为真值；关键错误样例包含错值、错引、单位/比较条件错误和应当停止却输出结论。
- 使用完整任务分母，包含失败、拒绝、耗尽、恢复和重试；报告置信区间，不只统计成功样本。
- 仅在价格版本可信且消费范围完整时报告货币成本；否则报告 token、调用、检索与时间，不宣称已经省钱。

### 9.3 必须报告的指标

| 指标 | 口径与用途 |
| --- | --- |
| 实验结论质量 | 独立核对值、单位、方向、数据集、比较对象、设置与限制；不以 schema pass rate 替代 |
| 证据支持与可追溯性 | 区分引用合法、能定位原文、原文确实支持断言；分别报告 |
| 缺证任务成功率 | 在允许补读且初始证据不足的预先分层中，正确完成任务的比例 |
| 诚实停止 / 错误成功 | 证据确实不足时是否披露不足或停止；是否把不合格候选报告为完整成功 |
| 无效循环率 | 无新事实重复动作、重复失败及无必要补读的比例与停止是否有效 |
| 总资源 | 所有模型调用/token、工具/检索执行、provider/tool retry、repair、恢复、消耗和未知保守预留 |
| 延迟 | 按相同任务边界统计端到端与分析阶段 p50/p95，包含队列、补读、失败和恢复 |
| 控制正确性 | 越权执行、预算突破、身份串用、错误发布、错误恢复及重复结算事件 |

### 9.4 继承的量化发布目标

以下摘录父 PRD v1.0 第 9.3 节，均为**拟议目标，不是已测结果**。父级若通过审查变更阈值版本，本专项随同更新，不维护第二套宽松标准。

| 门 | 目标 | 专项评测的判定边界 |
| --- | --- | --- |
| 控制正确性 | 适用确定性 AC 全通过，授权/gate/预算/发布边界绕过为 0 | 本专项相关控制场景必须通过，不能替代父级其他场景 |
| 标准任务额外开销 | 新增语义分类、动态 planner 和自适应专用 child fan-out 为 0 | 可直接通过本专项调用与派发记录核验 |
| 关键质量案例 | 预先冻结案例中新增错误发布、证据丢失、必需角色缺失为 0 | 本专项必须执行实验分析相关案例；总体案例仍需执行 |
| 需要补充工作的任务 | 相对既定分析，质量通过率差的 95% 配对置信区间下界不低于 0，并有“基线未完成、受控路径合格完成”的真实案例 | 两组局部评测可验证实验分析分层，不代表覆盖全部自适应任务 |
| 标准任务延迟 | 同环境、同材料状态下，服务端 active-time p95 不高于既定路径的 1.15 倍 | 冷启动、人工等待单列；失败不选择性排除；不能拿单个 loop 耗时替代规定的任务边界 |
| 总体语义非劣 | 相对同质量 profile 的始终规划基线，质量通过率差的 95% 配对置信区间下界不低于 -2 个百分点 | 必须有父级相应基线和正式数据；两组专项结果不能宣称该门通过 |
| 总体混合工作量 | 满足质量门后，相对始终规划的平均模型 token 至少下降 15%，含路由与重试 | 不将对一次生成的成本变化冒充该指标；必须完成父级规定比较 |
| 恢复与回滚 | exact identity replay、重复投递、取消、crash、rollout 回滚证据齐全 | 本专项交付适用部分证据，父级总 release 仍独立验收 |

### 9.5 发布规则

- 控制、授权、质量和恢复要求先于成本收益；任一 P0 控制验收失败不得发布，即使平均成本下降也不能豁免。
- 专项真实模型结果须证明在目标缺证任务上存在收益，同时不靠质量降级、丢弃困难样本或减少必需角色节省成本。具体数值门与统计判定须在留出前冻结到既有评测证据合同，不在运行后追认。
- 总体 release 的量化目标与统计口径继承父 PRD 第 9.3 节；本文不另设更宽松阈值，也不把父级拟议目标当作已有测量结果。
- 适用的执行、证据质量和桌面生命周期 owner 的 release evidence 必须满足；局部专项通过不改变这些依赖的完成状态。
- 尚无充分真实模型证据时，明确标记“控制接线已验证 / 语义收益未验收 / 未发布”，不得以“已支持多轮”掩盖产品验收缺失。

## 12. 风险与处理原则

| 风险 | 必须落实的处理 |
| --- | --- |
| 仅接上 Runner 就宣称完成 | 以真实动作、工具执行、观察回填与 gate 记录证明业务闭环，而非检查类名 |
| 只有文本补读，没有合法证据 | 将补证接纳及新版本 refs 作为 P0，引用资格与工具成功分开 |
| 内外重试叠加导致成本失控 | 共用请求账本，派发前预留，所有实际调用与未知结果入账，恢复不清零 |
| 模型无必要地读取和重复尝试 | 允许首轮提交，限制工具与返回量，使用无进展检测和简单任务成本指标 |
| 格式通过被误认为结论正确 | 确定性合同 gate 与独立语义评测分离，保留错值、错引、无法支持结论的对照 |
| 在真实材料中出现指令注入 | 文档和工具结果只作为数据；控制策略来自已冻结合同，不能由材料扩权 |
| 恢复重发未知操作或换版本继续 | 核对 receipts 和 pending 状态，只按已声明幂等策略重试；版本缺失失败封闭 |
| 专项范围膨胀到通用研究平台 | 固定单论文实验分析首版；跨论文、额外 planner、训练与递归委派另行立项 |
| 为赶交付放宽整体发布门 | 专项文档和局部评测不替代父 PRD、OpenSpec 与上游 owner 的资格 |
