# Research 工作状态与上下文窗口切换 PRD

## 1. 文档状态与决策摘要

- 变更：`research-context-state-rollover`。
- 状态：待实施提案；本文中的能力、门槛与指标均为需求，不代表已经实现或已经测得。
- 源码观察基线：`main` / `4c3e2a70`；本次基线核对为源码检查，没有运行验证或生产收益测量。
- 首期场景：单论文 Paper RAG 的多轮检索、补证和回答，贯穿真实 application service 与 Research / Harness 接线。
- 产品决策：首次读证据时一并记录结论、适用条件、必要短原文及来源；以结构化工作状态持续研究，按预算重建模型窗口。
- 原始历史保存在窗口之外并可授权回读；摘要与笔记可以使用，但不得取代事实、条件、核验范围和冲突记录。
- 代价控制：复用已提交状态与有效核验结果，按实质变化或疑点回查，不默认给每条记录、每轮对话或每次窗口切换增加核验调用。

## 2. 要解决的问题

用户研究同一篇论文时，会先问方法，再追问实验设置、适用范围和例外，最后要求形成可引用的判断。
如果持续携带全部对话、检索片段和工具输出，输入不断变长，费用及等待时间随之增长，也更容易超出模型窗口。
如果只保留自然语言摘要，早先出现的实验前提、限定词或未解决疑点可能随压缩消失，后续回答把局部结论说成普遍结论。
如果为了避免遗漏而每轮逐条读取原文并独立核验，额外调用又可能抵消上下文优化的收益。
本变更要让系统保留足够继续任务的工作状态，并把回读与核验集中在需要证据的地方。

以下是用于说明需求的合成案例，不是项目线上故障记录，也不是任何论文的真实实验结论。

| 情境 | 原始证据与操作 | 风险 | 本期要求 |
| --- | --- | --- | --- |
| 已记录条件丢失 | 原文为“小样本设置下，A 的准确率高于 B”；首次状态完整，后续摘要只剩“A 比 B 好” | 已知限制被移除，回答过度泛化 | 结论与已记录条件作为一组进入最终 provider 上下文；缺条件的候选或投影不得通过 gate |
| 首次读取就遗漏 | 首次抽取只记录“A 比 B 好”，同时保存了原文引用 | 引用存在但状态从未记录“小样本设置、准确率指标” | 对关键结论、范围扩展或疑点按需读取对应内容，补充条件并使相关下游判断失效；不能声称程序能发现所有语义遗漏 |
| 反复确认相同内容 | 同一结论、条件、来源版本和问题范围均未变，每轮重新核验 | 增加费用与时延，未带来新的证据 | 复用有效记录；证据仍在当前窗口时直接使用，必要时以证据批次组织核验 |

“可以回查原文”表示有纠正机会，不表示摘要、抽取或整个研究过程无损，也不保证零事实错误。

## 3. 目标、非目标与范围

### 3.1 产品目标

1. 用户跨越多个模型窗口后，仍能得到带适用条件、来源与明确不确定性的连续研究回答。
2. 已提交的结论、条件、核验范围、未决问题和证据关系可恢复、可追溯，避免依赖某一轮自然语言摘要。
3. 系统能在有限预算内选择保留、回读、核验、拆分或停止，用户可看到部分完成与证据不足的边界。
4. 在质量不退化的发布门槛下，降低代表性长任务的整体模型成本；收益必须用固定条件的配对评测证实。

### 3.2 V1 范围

- 接入一条真实单论文 Paper RAG 纵向链路：开始问题、检索、首次证据抽取、多轮补证、状态提交、窗口切换、最终回答。
- 覆盖单 run 内恢复与局部依赖失效；候选必须带状态版本和 attempt 身份，阻止过期结果覆盖新状态。
- 复用现有领域模型与控制面，新增 capability 对应 `research-working-state`、`harness-context-window-rollover`、`research-evidence-recheck-policy`。
- 在现有结果和诊断中呈现核验范围、争议、缺失信息、停止原因与成本；接口仍通过 application service。

### 3.3 非目标

- 不在本期接入 Reader Repair、跨论文综合或重建并行调度器；这些业务接入需后续独立验收。
- 不迁移所有 conversation caller，不改变未启用策略的现有调用，不从已经丢失的 legacy 原文中伪造归档。
- 不建立新的 Workflow runtime，不让 LLM 决定路由、gate 通过、工具授权、记忆写入或发布。
- 不把工作状态自动提升为跨任务长期记忆或 active skill，不承诺摘要无损、语义零遗漏或生产性能提升。

## 5. 用户旅程与可见行为

1. 用户选择一篇论文并提出问题。系统固定本次问题范围、论文身份和预算，确认启用路径具备授权归档能力。
2. 系统检索相关片段。在首次阅读这些片段的同一模型调用中，生成结论候选、已识别条件、必要短引文、来源和疑点。
3. Research 提供领域校验规则与语义核验 port；Harness 执行确定性 gate，只有接受后的状态版本可供后续窗口使用。
4. 用户继续追问。系统沿用相关状态及证据；问题范围扩大、来源变化或出现新推断时，只对受影响内容补证或回查。
5. 接近窗口预算时，系统在已提交的安全边界重建输入，将当前问题、相关结论及条件、核验状态、待办和必要证据带入新窗口。
6. 最终回答提供有依据的结论、适用范围与引用，说明未解决的冲突或缺失条件；预算耗尽时可交付已核验部分，但不得显示为完整成功。
7. 中断后恢复时，系统从 canonical 接受历史恢复状态与预算，不重新执行历史工具外部写，不把摘要当成恢复真源。

正常窗口切换无需用户确认；只有确实影响回答的问题范围不明确时，沿用现有澄清规则。

## 6. 信息的职责与生命周期

| 信息形态 | 负责保存什么 | 使用限制 |
| --- | --- | --- |
| 当前模型上下文 | 本轮任务所需的状态投影、证据片段与调用协议 | 有界且可重建；不是唯一存储，也不是权威历史 |
| 研究工作状态 | 当前目标、结论及条件、来源、核验范围、冲突、依赖和未决问题 | 只使用已接受版本；任何语义变化都需候选、gate 与提交 |
| 原始归档 | 按授权保存的用户消息、工具 observation、源片段及其身份和校验和 | 只追加或版本化；回读需授权；归档存在不代表内容已被模型核验 |
| 交接笔记 / 摘要 | 当前进度、导航、下一步与来源定位提示 | 从状态派生；可以更短，不得修改或覆盖事实与条件 |
| 跨任务记忆 | 经既有 policy 授权沉淀的可复用经验 | V1 不自动写入；不等同于本次会话工作状态 |

结论记录至少应表达稳定身份、`statement`、适用 `scope`、`conditions`、来源引用与校验和、核验状态及范围、依赖身份和版本。
记录还应保留必要短引文或可回读定位、未决疑点、产生它的候选 / attempt 身份，以及接受该版本的 canonical event 序号。
条件需区分“已记录限制”“尚不清楚”和“经核验不适用某项限制”；空数组或字段缺失不得自动解释为“无条件成立”。
核验状态至少区分候选、待核验、范围内支持、缺少信息、争议与失效；名字可在 schema 设计中确定，语义不可合并。
“范围内支持”只对记录的来源版本、问题范围和核验内容有效，不能变成整篇论文或任意后续推断的通行凭证。

## 7. 功能需求

### FR-01 首次读取时联合记录

首次读取一个证据批次时，同一调用应产生结论、识别到的适用条件、必要短原文、来源与疑点候选。
不得为了形成这些初始字段，默认先抽取结论再新增逐条原文回读调用；批次内共享证据应复用。
模型可能漏掉首次语义条件，系统必须保留这一能力边界，并让疑点和关键结论进入有界内容核验策略。

### FR-02 版本化工作状态

工作状态以明确的 run、论文、问题范围、schema / policy 版本组织，支持追加、修正、失效及争议保留。
删除条件或扩大结论范围必须是显式语义变更，附有来源和变更原因；不得随摘要、格式整理或投影静默发生。
已记录限制在未经接受的修正前持续有效；旧版本及拒绝理由仍可审计。

### FR-03 候选与控制权分离

Research 定义事实、条件、支持关系及语义校验 port；LLM 仅输出候选和核验意见。
Harness 决定预算、权限、重试、replan、提交与终止，并以确定性 gate 检查身份、版本、引用、字段保全及核验策略要求。
执行遵循有界 `PLAN -> EXECUTE -> VERIFY`；`max_replans`、`max_turns` 和 retry budget 共同约束继续执行，每次 phase transition 都写入 durable transcript 或 event log。
结构检查可证明已记录条件未丢失，不能证明来源中的所有隐含前提已被识别；语义核验模型也不提供零遗漏保证。

### FR-04 原始归档先于裁剪

启用新策略的调用必须在既有 conversation compaction 或消息替换之前，完成可回读的独立归档及完整性检查。
原始 observation 应先 durable，再进入候选与状态提交；引用绑定租户 / 会话授权、来源身份、版本和内容校验和。
归档失败、原文缺失或访问被撤销时，不得以该路径裁掉唯一原文并继续宣称可恢复；返回类型化原因或保留安全输入后受控停止。
历史只剩摘要的 legacy 会话必须标明原文不可恢复，不能通过导入把对应结论默认升级为已核验。

### FR-05 canonical 接受事件与投影

提交顺序固定为：写入状态 artifact 并确认完整性 → 以 expected sequence CAS 写入 canonical 接受事件 → 更新状态投影。
接受事件携带 artifact 身份和校验和、父状态版本、候选身份及核验依据；事件成功之前，新状态不得激活。
artifact 成功但事件失败仅产生未激活 artifact；事件成功但投影失败可由历史重建；checkpoint 只加速恢复。
同一提交身份与相同内容重试应幂等；同一身份不同内容、旧父版本或过期 attempt 必须拒绝，不能覆盖已接受版本。

### FR-06 状态驱动的上下文组装

每次调用前按当前问题与依赖选择已提交记录，先确定性组装任务目标、相关结论组、未决问题、必要证据和最近协议消息。
可选摘要仅承担导航与进度压缩；其生成也受预算和权限约束，不能产生新的事实权威或修改状态。
最终送往 provider 的内容必须同时包含结论、已知条件、核验范围与不确定性，不能只在外部状态保存条件而向模型只发送结论。
不相关记录可整体不进入本轮窗口；一旦使用某条结论，其相关条件与核验限制不得被单独裁掉。

### FR-07 预算内窗口切换

实际 provider 输入必须满足 `input_tokens <= context_window - output_reserve - safety_margin`，包括系统提示、工具 schema 和封装开销。
按目标模型的 token 计算方式及实际请求结构验收；不同模型不能共享未经验证的固定字符换算。
窗口切换只发生在提交完成的安全边界，保留 run、权限、累计费用、剩余预算、重试计数、pending call 和工具事务身份。
尚未满足安全边界时延后切换或受控停止，不能截断正在处理的调用与响应协议来腾出窗口。
受保护内容仍超窗时，Harness 可缩小本轮工作集或有界拆分；仍无法满足则返回类型化停止，不通过裁剪条件勉强发起调用。

### FR-08 按需原文回查

范围变化、来源版本变化、依赖内容变化、新推断、关键结论尚未满足核验策略或发现疑点时，才安排受影响证据的回查。
相同范围、来源和记录版本复用有效结果；普通窗口切换和无实质变化的下一轮对话不独立构成回查理由。仅展示排版变化且仍使用同一已核验命题记录可复用；模型自由改写不能仅凭“只改措辞”标签确定含义不变，无法确认命题和范围身份时按新候选处理。
所需证据仍在本轮有效上下文时直接使用，不额外发起存储读取；需要外存内容时优先读取精确定位片段。
不能只凭“引用可解析”判定内容支持；需要语义判断时，向核验 port 提供真实证据和明确待核验问题。

### FR-09 分组核验与有效复用

共享同一证据批次或相邻原文的结论可合并核验，输出仍逐条绑定结论、条件、来源及核验范围。
复用 key 至少包含授权范围、问题 scope、来源身份与 checksum、claim / conditions 内容版本、依赖版本、核验 policy 和 verifier / prompt revision。
相关任一依赖变化即失效；复用不得跨越授权边界，不得把旧版本核验意见贴到新内容上。
模型自信、多模型多数票和版本较新均不能替代来源内容；provider prompt cache 可省费用，但不会释放上下文容量。

### FR-10 冲突分类与局部失效

状态和原文不一致时，先区分不同范围、缺失条件、来源更新、抽取错误、证据不足和真正矛盾，再执行相应处理。
真正矛盾进入 `disputed` 并保留双方证据及范围；没有支持证据不等于存在反证，较新来源也不自动胜出。
结论或条件变化只使相关依赖失效并局部重验；没有受影响的已核验内容继续有效。
依赖关系无法确定时必须标记不确定并限制下游使用，不得假定不受影响。

### FR-11 关键结论与最终回答准入

Research policy 应在评测和灰度前固定“关键结论”的判断范围，例如直接回答用户目标、扩大适用范围或支撑最终推荐的判断。
最终生成优先使用满足当前范围核验要求的记录；尚未满足要求的内容只能带缺证、待核验或争议标记呈现。
相关条件缺失、核验过期或来源不可用时，Harness 必须限制该结论的确定性表达；不能由模型自报 confidence 决定通过。
已核验部分可独立交付，但整体结果需保留未完成项和完成状态，不能把部分支持包装成完整研究成功。

### FR-12 有界成本与终止

核验策略必须同时限制调用次数、输入 / 输出 token、原文读取次数 / bytes、单问题尝试次数及批量 item / token 上限，配置值在 run 开始时固定并记录；可可靠估算费用时同时配置任务总费用上限。
回查、摘要、失败重试、语义核验与子任务均消耗同一任务总账；子任务或窗口切换不得重新获得一份完整预算。
预算不足时优先保留已验证信息与未决事项，返回证据不足、缺少条件或预算耗尽的类型化结果，不启动无界补证循环。
调用前预留输入与最大输出预算，调用后按实际 usage 结算。超时或 usage 缺失保留未决 reservation，重启和换窗口不能释放；费用未知必须标明 unknown，以有限 token / call 上限控制，不能填零或声称已达到费用目标。配置了货币上限但无法进行保守费用准入的部署不得以 unknown 绕过该上限。

### FR-13 恢复、replay 与工具外部写

恢复前验证 run / Graph 身份、事件连续性、artifact 校验和、state / policy 版本及预算账；不一致时受控停止或隔离。
纯 replay 只消费已持久化历史、artifact 和结果，不调用 live LLM、检索源、工具或子任务。
有外部写的未决调用需先按稳定操作身份对账，再由既有 Harness 规则决定恢复；超时不等于没有执行。

### FR-14 授权与数据最小化

原始归档继续遵循现有授权、脱敏和保留策略；受保护数据不得因归档或回查进入无权访问的模型上下文。
引用解析和复用前检查当前访问权；权限撤销或源删除导致不可回读时保留可审计状态并阻止虚假核验。
归档 artifact 与接受事件分别记录数据身份和控制事实，不要求把敏感原文复制进每个事件。

## 8. 回查与冲突决策表

| 触发情况 | 默认动作 | 状态与使用边界 |
| --- | --- | --- |
| 范围、来源、条件、policy 均未变 | 复用已接受记录；不新增独立核验调用 | 保持已有核验范围 |
| 只改变展示排版，仍引用同一已核验命题记录 | 进行结构与版本检查 | 自由语义改写不能仅凭标签认定等价 |
| 问题由特定数据集扩展到一般情况 | 读取影响范围的证据并提出核验候选 | 原局部支持不能直接覆盖扩大范围 |
| 首次抽取可能缺少前提 | 对关键或有疑点结论按批次回查原文 | 补条件并使相关下游失效；不能承诺全部检出 |
| 原文与结论条件不同 | 检查范围差异与抽取错误，提出修订 | 经 gate 接受后更新；保留旧版本 |
| 新来源与旧来源真正矛盾 | 保留双方、标注争议，按 policy 补证 | 禁止仅凭时间或投票覆盖 |
| 来源不可读、checksum 变化或授权撤销 | 拒绝复用旧核验结果，记录明确原因 | 受影响结论转为缺证或失效 |
| 回查预算耗尽 | 停止新增核验，交付可支持的部分 | 明示缺证 / 缺条件及未完成范围 |

## 9. 费用、质量与测量要求

性能数字是待验证目标，不是现有成果，也不能直接采用外部文章的提升比例。
评测开始前冻结模型及版本、论文和任务集合、基线策略、预算、关键结论规则、评分方法与发布阈值，避免事后选择有利口径。
采用相同任务的配对离线基线，覆盖短任务、接近窗口、跨多窗口、密集条件、真实冲突、缺证和预算耗尽场景。
效率门槛为：在答案范围可比的配对完成任务中，总模型 token 与费用至少一项降低，另一项不恶化；统计必须包括所有摘要、核验、重试及子 agent 消耗，不能只计算主回答输入。具体节省幅度须由评测给出，不预设未经测量的百分比。
核心条件保留的确定性回归必须全部通过；标注关键范围用例不得出现新增条件遗漏或无依据泛化；盲审 supported-claim precision 与 task completion 不劣于基线，非劣效口径在评测前固定。不得靠提前退出、缩减回答范围或大量拒答制造效率收益。
报告样本数、配对结果、统计区间、失败样例、费用与时延；样本或区间不足以支持结论时，不扩大灰度。
对短任务报告附加开销，不能用长任务节省掩盖简单问题的退化；缓存命中、费用下降和 context token 下降分别呈现。
每个 run 至少记录输入 / 输出 / cache token、实际费用、调用与核验次数、回读 bytes、rollover 次数、整体与关键阶段时延、完成状态及原因。
无法获得的 provider 指标必须标明估算方式或缺失，不能补零并宣称节省；生产收益只能在后续真实运行观测后报告。

## 10. 边界与异常处置

| 边界或故障 | 必须满足的行为 |
| --- | --- |
| 归档写入失败或完整性不匹配 | 阻止使用新策略裁掉唯一原文；状态不升级为可恢复 |
| artifact 写入后、接受事件前崩溃 | 新 artifact 不激活；恢复仍使用上一个已接受状态 |
| 接受事件成功、投影更新失败 | 由 canonical 历史重建一致投影，无需重跑语义抽取 |
| 过期 attempt 或并发旧版本提交 | CAS / 身份检查拒绝，记录拒绝事实，保留最新状态 |
| protected 内容超过预算 | 缩小工作集或有界拆分，失败则类型化停止；保留条件完整性 |
| rollover 时仍有 pending tool call | 沿用调用身份和事务状态，不能漏掉协议响应或重复外部写 |
| legacy 仅剩摘要 | 标记原文不可恢复；重新获取真实来源前不自动授予 verified |
| 回查结果仍不确定 | 保留 uncertainty 与 missing information，不把模型投票当成裁决 |

## 11. 职责边界与实施顺序

| 责任方 | 职责 |
| --- | --- |
| Research domain / application | 结论与条件语义、证据支持关系、关键结论规则、局部失效、单论文产品接入 |
| Harness | `PLAN -> EXECUTE -> VERIFY`、确定性 gate、预算 / 权限、提交、窗口组装及恢复控制 |
| Infrastructure adapters | 授权归档、artifact 与 canonical event ports、实际 token / 费用与模型调用适配 |
| LLM / 子任务 | 在授权证据与预算内提出候选；不持有接受、状态覆盖、工具授权或发布决定权 |
| 验收与发布负责人 | 固定评测协议，审查结构回归、盲审质量、总体成本与灰度 / 回滚条件 |

实施按以下顺序推进；前一阶段的退出条件未通过，不扩大后一阶段接入范围。当前所有阶段均未完成。

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| G1 契约与可恢复存储 | 状态 / 条件 / 来源 / 版本契约、归档、接受事件与投影 | 条件保全、CAS、失败注入及纯 replay 验收通过 |
| G2 真实单论文链路 | 首次联合抽取、多轮补证、按状态组装与窗口切换 | 真实 application service 纵向测试通过；没有生产 fake 路径 |
| G3 有界回查策略 | 触发规则、分组核验、复用、冲突分类与成本总账 | 改动失效与不改动复用均通过，所有预算都能终止 |
| G4 配对评测与灰度 | 冻结评测报告、诊断、显式 opt-in 与回滚验证 | 结构、质量和成本发布门槛同时通过且证据充分 |

| AC-13 | FR-09 | 多条结论共享证据批次 | 可批量核验且每条结果仍绑定明确范围和来源；成本按实际调用计入 |

| AC-15 | FR-10、FR-11 | 修改共享前提并保留一条无关已核验结论 | 相关下游失效，无关结论保留；最终回答不确定性表达正确 |
| AC-16 | FR-11、FR-12 | 分别耗尽 calls、tokens、reads / bytes、attempts 和已配置费用上限；模拟 usage 缺失 | 无越界继续核验；未决 reservation 保留；可支持部分可交付，整体不标为完整成功 |

| AC-20 | 第 9 节 | 固定模型 / 任务 / 预算的配对离线评测与盲审 | 输出完整成本与质量报告；未达到发布门槛或证据不足则不扩大灰度 |

实现验收还需执行与改动范围匹配的测试、项目代码 smoke gate 及 `openspec validate research-context-state-rollover --strict`。
文档校验通过只证明规范结构可接受，不能代替上述行为验收、真实链路检查和收益测量。

## 13. 灰度与回滚

V1 通过显式策略开关接入单论文新 run；归档能力、授权或配置不满足时拒绝启用，不能静默落到不满足契约的压缩路径。
先进行离线评测和受限范围灰度，逐批复核条件丢失、错误确定性表达、冲突处理、恢复失败、token、费用和时延。
发现条件被静默删除、授权越界、状态错提交或外部写重复等正确性问题时停止扩大灰度并关闭新 run 的策略 admission。
回滚不删除归档、接受事件或已提交版本；活动 run 使用固定 policy 版本安全收尾或类型化停止，不能在窗口切换时换成未经验证的旧语义。
恢复启用前需定位根因、补齐有意义的回归并重新通过相关门槛；质量或成本收益证据不足时维持受限范围。

## 14. 外部依据与适用边界

以下材料提供设计参考，不代表项目已实现对应能力，也不构成项目成本或质量指标的测量依据。

- [Anthropic：Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：摘要、结构化笔记与按需读取可用于管理长任务上下文。
- [LangChain：Deep Agents context engineering](https://docs.langchain.com/oss/python/deepagents/context-engineering)：参考外存、摘要与原文保存的组合；本项目仍需独立实现授权及 durable 接受契约。
- [The Complexity Trap](https://arxiv.org/abs/2508.21433)：参考工具 observation masking 与摘要的成本比较；其编码评测不能直接套用到论文研究。
- [Self-RAG](https://arxiv.org/abs/2310.11511)：参考按需检索和核验思想；其训练方法不能通过增加一段 prompt 等价获得。
- [Claude prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)：参考重复前缀的计费与时延优化；cache 不增加模型窗口容量，也不证明条件已被模型使用。
