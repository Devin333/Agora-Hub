## Context

本设计对应 [PRD](prd.md)，状态为拟实施。当前 `CitationVerifier` 核对引用 ID，`ResearchQualityGate` 聚合 gate 结果；两者均未实现在线语义分歧处理。现有 Graph 的 `verify_claims` / `quality_gate` 失败不会继续生成并发布阅读器和论文卡片。通用等待、审批及 skill promotion 的合同可提供设计约束，不能直接宣称已具备 claim 评审与规则发布产品。

新增逻辑归 Research domain/application/graphs。Harness 保持唯一控制者，继续执行有界 `PLAN -> EXECUTE -> VERIFY`；模型和人工只提供观察。所有新能力默认关闭，不替换现有主链和终态成果提交协议。

## Goals / Non-Goals

**Goals:**

- 将一个“人工与系统意见不同”的请求转成可定位、可修正、可关闭的案卷。
- 同时允许检查工具、标准、证据处理和评审意见被纠错；让未解决分歧保留其真实状态。
- 冻结 claim、研究目标、论文、证据和规则版本，使复核、重试与历史解释一致。
- 支持真实阅读页操作、持久化和独立规则发布；第一阶段仍要求整份正式报告通过验收。

**Non-Goals:**

- 不将语义核验形式化为科学真理证明，不承诺人工或多个模型一致必然正确。
- 不引入运行之外的平级调度器，不增加模型在 VERIFY 中的调用或直接发布权限。
- 不实现受限正式报告、跨论文仲裁或独立复现实验平台。
- 本变更文档交付期间不实现代码，不修改已有面试答案。

## Decisions

### D1. 使用不可变修订和可重算的判定输入

`ClaimRevision` 与 `ReviewBinding` 冻结 PRD 第 6 节的信息。业务主键之外保存内容 checksum；不以一个可变 evidence ID 代表不变材料。绑定同时固定类型要求、目标必要项和评审策略，防止删句、改名或换模型后沿用旧通过记录。

评审意见追加保存，修正以 `supersedes_observation_id` 指向同一评审者的旧版本。案卷通过 revision/CAS 串行接纳有效观察和关闭记录。旧版本意见可以作为新案卷待复核的线索，但必须重新绑定并确认适用性，不能直接参与新版本判定。

选择该方式的原因是“谁说过什么”和“现在能发布什么”需要分别解释。覆盖旧意见虽然存储简单，会丢失误拦依据并让恢复无法复算。

### D2. 区分执行结果、证据关系与发布状态

检查结果先记录 `COMPLETED / UNAVAILABLE / INPUT_INVALID`，完成有效执行后才附带要求项的 `PASS / FAIL`。评审观察记录具体支持范围、反证或缺口，不暴露可授权的最终 `passed` 字段。

Research resolver 是纯函数，输入为冻结合同、已接纳观察和当前案卷事件，输出 `ResolutionRecord` 候选。确定性 gate 重新校验绑定和状态推导；Harness 接纳后才产生业务状态。resolver 不加载网页、不调用模型、不依靠墙上时钟，也不读取可变的“最新规则”。超时、撤回和规则隔离以已持久化事件作为输入。

语义结论来自有限材料上的可质疑评审。确定性执行只保证相同记录按相同策略得到相同处理，不证明人类判断为真。`SUPPORTED_WITHIN_SCOPE` 必须显示范围与所依据的评审策略，不能称为“系统证明正确”。

至少保留 PRD 的七种 claim 状态。关闭原因与状态正交，预算耗尽不能把“仍有争议”改成“已反驳”。使用一个 `approved` 布尔值会丢掉这些区别，因此不采用。

### D3. 在质量验收前处理诊断，失败的质量门仍不可越过

启用后的 Graph 在候选分析汇合后、最终 claim 与报告质量验收前，声明评审准备过程：固定输入、收集检查观察、收集要求的独立意见、接纳异议、形成 resolution。步骤和允许的修复边预先冻结。若诊断需要完整候选报告上下文，先组装内部候选报告；该报告不具有公开引用。

诊断节点的 gate 检查“这份诊断是否真实绑定输入且结构有效”，它可以接纳“缺脚注”这样的有效诊断。**接纳诊断不等于接受该 claim**。只有支持记录满足合同后才能进入最终质量验收。非支持结果由 Harness 按显式策略选择补材料、等待、收窄候选或关闭；模型输出不得指定下一节点。

既有 `ClaimEvidenceGate@1` 和报告质量门失败仍阻止其后继。实施时增加精确版本的新 gate 与必要 failure/repair binding；不能通过把失败结果改成成功、移除旧 gate，或让普通后继承担隐式补救来接上流程。静态和局部动态分析入口须消费同一评审合同，不改变固定外层 Graph。

分析、机器评审及收窄建议在 EXECUTE 运行；VERIFY 只核对已记录输入。局部 `AgentLoop` 仍是语义 worker 的执行循环，不变成案卷调度器。任务预算、授权、等待与终态选择归 Harness。

### D4. 用具体争点选择纠错方式

| 原因 | 处理 | 不允许的捷径 |
| --- | --- | --- |
| 不同材料或断言范围 | 对齐固定视图或拆开不同 claim，形成新绑定 | 将不同问题上的赞成票相加 |
| 同版 PDF 有信息但证据投影遗漏 | 有界读取脚注、上下文、附录；产生新 evidence revision | 把人工描述直接当作原文 |
| 现有材料已充分但检查实现不适用 | 生成规则缺陷复现包；独立修复与关联重评 | 当场豁免失败项 |
| 候选过度外推 | 生成较窄的新 claim 并重检目标覆盖 | 用改句子掩盖未完成的研究目标 |
| 同一范围的解释仍相反 | 独立复核具体理由；有依据消除则新 resolution，否则保留争议 | 根据多数票或置信度宣布通过 |
| 原文、权限、检查工具不可用 | 有界恢复或记录不可核查 | 把工具异常写成反证 |

引文匹配保留规范化映射；数字与单位不能被清洗掉。计算器只处理已经定位且条件适用的值，明确百分点与相对比例、分母为零和舍入误差。含词匹配、模型抽取字段齐全均不证明同一实验关系。

首次独立人工复核对其他意见盲审。需要语义判断的实验比较/外推，默认至少一次独立人工复核；机器意见不单独解除该要求。额外复核必须说明争点怎样得到解决。若仍无依据区分双方，保持 `DISPUTED`。此默认值牺牲吞吐量换取初期可观察性，可在另经评测发布的策略中调整，不能由单个 run 临时变更。

### D5. 评审接口是提交观察和请求处理

以下为拟新增应用合同，命名在实施时遵循现有 API 约定，产品不直接依赖内部类名：

| 应用操作 | 关键输入 | 返回与权限 |
| --- | --- | --- |
| 查询案卷/结论详情 | 授权 scope、claim/case ID | 原文定位、可见意见、待解决项、状态及 revision |
| 提交异议/独立意见 | 完整 binding、expected case revision、幂等键、理由与依据 | 持久接纳或明确拒绝；不返回新发布授权 |
| 提交证据定位/收窄候选 | 对象修订、来源位置或候选、目标影响 | 候选引用，待 Harness 验证处理 |
| 请求重评 | 前次 resolution、实质新依据、目标规则版本 | 授权的新处理请求或关联 run，不能复活旧 run |
| 提交规则修订 | 规则版本、复现包、候选变更 | 规则维护流程中的候选引用 |

接口层只调用 Research application service；application 校验身份、作用域、版本和资源额度后，经 ports 写入事务性观察与事件。独立意见资格区别于规则维护资格；作者不能同时审批自己的规则候选。租户所有者的写权限也不赋予绕过质量门的权限。

盲审限制在服务返回数据中落实，不能只在页面上隐藏文本。评审者须有原文访问权；无法访问不发送受限摘录。来源和评审理由当作数据处理，不能注入路由、权限或规则配置。

### D6. 等待、幂等和发布竞态沿用一个控制协议

案卷状态是 durable events 的 Research 业务投影，复用 Harness wait/resume、lease 和授权入口。若现有等待适配器不能绑定所需的 claim/case revision，应先补充明确的通用等待合同和适配器，不能复用裸人工 `approve` 语义。

默认 2 次补材料、1 次额外独立复核、2 次有实质新依据重开。计数来自持久记录；与 run 的 turn/replan/retry/cost/deadline 取更严格上限。人工等待为 24 小时与剩余 deadline 的较小值，等待时释放活动执行资源。未完成复核不等于同意。终结后新材料建立关联重评。

观察与事件原子提交或通过可对账 outbox 保证同一接受语义；提交失败不推进投影。相同幂等键同内容返回原结果，异内容拒绝。关闭采用 CAS，不允许两个并发 resolution 同时成为当前记录。

正式发布授权绑定 claim/case/规则可用性 revision。接纳实质异议与发布前资格检查共享可排序的持久屏障；不能仅“先读状态、稍后发布”。复用 terminal intent/receipt 的 pending、committing、committed 状态及 fencing：异议先提交则旧授权失效；正式提交已先完成则走发布后复核。未知外部提交状态先对账，既不盲重试也不伪称未发布。事务无法覆盖外部成果存储时，以终态提交日志与幂等 receipt 明确线性化点，要求竞态和故障注入验证。

replay 只重建旧记录，不调用 LLM、来源、人工通知、规则发布或成果提交。使用新证据/规则复核是新 run，保留与原 run 的关系。

### D7. 将规则纠错独立于普通研究运行

新能力 `research-review-rule-release` 管理 checker、类型标准、评审 prompt、阈值和适用范围组成的版本包。它借鉴现有候选/验证/评测/发布机制，不能直接复用 skill promotion 并宣称语义等价。

流程为复现 -> 缺陷或标准变更分类 -> 候选验证 -> 开发集与留出集成对评测 -> 独立维护者审核 -> 版本化发布 -> 影响面登记。留出样本与答案对候选作者/运行环境隔离；质量和成本门槛在结果揭晓前登记。失败不得通过降低断言、删除反例或修改通过线绕过。

当前业务 run 冻结原规则。确认原规则失效时，记录版本/claim 类型隔离事件，停止受影响发布，当前核验不可用；新规则发布后建立关联重评。历史失败不重写。已发布产物由独立状态投影标记待复核，并传播到索引/卡片/下游消费；尚未完成传播时，消费入口必须读取当前隔离状态或阻止读取，不得依赖缓存最终一致性继续信任。

规则回滚切换未来准入版本并保留影响面。若某项改动实际涉及 active skill，仍必须先记录业务修复 memory、consolidate 成 procedural strategy，再进入既有 Harness skill evolution 的 held-out eval、promotion、versioned release 与 rollback；本规则流程不提供绕行入口。

### D8. 第一阶段只扩展评审，不扩大正式发布种类

完整报告必须覆盖冻结目标的必要项，且所有待核验断言均有当前支持记录、无相关开放争议或规则隔离，再通过原质量门及 controller-terminal publication。删除不必要的坏候选允许，但不得删除必要研究目标。必要目标调整必须来自用户明确的新目标版本。

诊断页可以展示已支持分析、未知实验和争议，所有内部引用按候选/诊断权限读取，不能产生正式 paper card、reader artifact 或可被误当完整报告的公开引用。后续受限正式报告另提变更。

新能力中的阅读/复核 UI 是本次产品范围；已有 `research-runtime` 中“Research UI Out Of Scope”记录的是此前后端重建阶段，本变更不重开那个阶段的 UI 迁移义务。新 UI 合同归 `research-claim-review`，通过现行 Research 应用服务提供。

## Risks / Trade-offs

- **独立评审仍可能共同误读**：定位依据、隐藏先前意见、检查反例并允许新材料申诉；不给出客观真值保证。
- **人工等待降低自动化吞吐量**：按 claim 类型/租户启用、测量成本、采用持久等待；不以放弃核查换取展示完成。
- **恶意或重复异议耗尽资源**：权限与实质性接纳、幂等关联、不可清零的额度；被拒绝的有效权限内请求保留可解释原因。
- **规则隔离影响大量旧产物**：版本依赖索引和消费时状态检查；保留原产物，修正发布新版本。
- **前后端或缓存状态不一致**：服务端强制盲审与发布资格、revision 条件写、消费侧隔离检查，不能只靠页面标签。
- **评测迎合某位评审**：样本范围与理由、独立标注、争议样本单列、论文级留出；同时报告误拦、漏放、弃判和成本。
- **规则生命周期和并发提交工程量较大**：分阶段开关；依赖未具备时 enforce 预检失败，不提供名义可用的简化后门。

## Migration Plan

1. 先固定旧主链回归和评审数据模型；迁移只增结构，历史记录标记为原引用检查合同，不回填为语义已核验。
2. 建立真实来源、持久评审、解析定位、独立评审与规则包适配；单元 fake 仅用于测试。
3. 接入候选诊断 UI 和完整受控 Graph，执行权限、幂等、重试、发布竞态与 replay 集成。
4. 在授权范围和独立资源上限内运行 shadow；不影响生产发布，不自动发送人工请求，不让影子记录获得正式权限。
5. 完成 PRD AC-01 至 AC-26、预登记阈值与留出评测后，才按类型/租户启用 enforce。缺规则、持久化、评审服务或额度时拒绝准入。
6. 回滚停止新准入，活动运行按冻结策略关闭或取消；保留案卷和产物隔离。不得将新版争议任务静默改成旧模式继续发布。

## Open Questions

以下是实施阶段必须登记的发布条件，未满足时保持关闭，不构成当前文档的虚假已完成项：

- 评审服务的人力与身份隔离如何部署，哪些 claim 类型优先启用；默认语义比较需要独立人工的规则已确定。
- 从真实单篇论文建立多少留出样本、如何量化各类误拦/漏放和可接受成本；不得在看到候选留出结果后再设阈值。
- 实际成果后端的提交线性化点与 receipt 对账路径须在并发集成任务验证；不能仅以进程锁证明跨进程一致性。
