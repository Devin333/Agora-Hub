## 4. 用户旅程

### 4.1 首次使用

用户执行 `doctor`，获得本机依赖和能力清单；按说明配置真实 provider 和解析路径。构建并启动后，首次初始化本地账号，登录正式 Research 首页。公共 OTP/OAuth 不作为前置条件；用户自行输入口令，日志和证据不记录口令。

### 4.2 搜索、导入与整理

用户输入研究问题，检查可编辑的约束，选择真实结果或粘贴来源。上传 PDF 后能看到实际导入状态；失败后保留输入、导入标识和可用的重试动作。打开论文，浏览章节/PDF、记录笔记、加入分组、选择材料；界面准确区分本地待保存、服务端已保存和冲突。

### 4.3 分析与报告

用户明确选择一篇论文及其当前来源修订，提交分析或论文问答。前端展示后端提供的状态与诊断；没有细粒度事件时只显示等待，不编造阶段或百分比。完成后能追溯 run、证据定位、质量结果和 artifact；质量失败结果仅用于诊断，不能作为通过的报告导出或展示。

材料草稿可以含多篇论文。自动分析的必交付范围是一篇论文的既有 Research 路径，多篇材料只做有明确来源的整理/草稿和已有确定性比较；界面不能将其称为自动综述。

### 4.4 继续使用与故障恢复

关闭标签页、重新登录或重启服务后，用户可恢复已提交的材料、会话、报告和精确阅读位置。请求中断后先核对既有 request/run 身份，不能盲目创建第二次分析。进程重启不承诺任意未提交工作自动成功；无法确定的运行应显示中断/待核对并提供受控下一步。

### 4.5 备份与更新

用户通过本机工具创建一致性备份，查看包含项、排除项和校验摘要。在隔离目录恢复并校验后，才允许切换到恢复的数据。更新使用可追溯版本；恢复旧版本必须验证代码、依赖和数据 schema 的兼容性。

## 5. 功能要求

### D1/D2：部署 profile 与能力

- 默认 Windows 单机、`local-desktop` profile、仅 `127.0.0.1`，统一前后端 origin、端口及配置来源；不得静默改绑 `0.0.0.0`。
- 复用根 `.env` 与现有配置解析，新增项有说明和严格校验；不建立同名不同义的第二套环境变量。配置检查只显示存在性、受影响能力和脱敏错误。
- 分开表示 `configured`、`reachable`、`verified`；doctor 默认无外网请求，显式 live probe 才验证真实网络/provider，且有超时、请求数和费用上限。
- 启动固定 `.venv` 与前端 lockfile；不静默安装软件、更新依赖、下载大模型或更改用户既有密钥。
- 本版成功验收至少要求一条真实论文来源、PDF 导入路径和真实单论文分析/问答路径可用；扫描件 OCR、dense retrieval 等未选择能力有明确标识。

### D3：身份与数据归属

- 本地初始化只允许创建第一个账号，重复请求不能重建或覆盖既有用户；不得创建写死的演示账号。
- 前端 guard 不是授权来源。BFF/API 必须解析真实会话，并在 application service 处校验 workspace、run、artifact 与报告 owner；不能信任浏览器提交的 user/tenant 字段。
- 服务 API 凭据与用户会话分开处理，不能把所有浏览器用户映射到共享管理员身份。
- 本机 HTTP cookie 例外只在显式 profile、确定的 loopback bind/origin 下生效；保留 HttpOnly、SameSite、有效期和退出撤销。非本机部署保持 HTTPS/Secure 要求。
- 业务写操作检查同源及有效会话；bootstrap/login 等既有认证入口允许无会话访问，但仍检查认可 origin、请求合法性、频率限制及初始化状态。导出、私有 PDF 和 artifact 同样受授权保护。资料、密钥和日志不得通过 Next 静态目录直接公开。
- 访客已有内容只能显式导入，退出/会话切换清理内存与缓存；保留原 owner 的可恢复草稿，不自动混合账号。

### D4/D5：正式工作区与连续性

- 在本机 profile 将 `/` 作为 Research 正式入口，统一论文、阅读、分组和报告路径；原 `/design-demo` 深链接按设计迁移，保留经过校验的查询及续读定位。
- 新写入历史使用正式路径；旧记录采用版本化、可重复执行的规范化。原入口仅保留迁移重定向，避免两套独立实现。
- 正式 UI 使用既有设计语言；导航、按钮、加载/空白/失败/重试、保存/冲突、过期登录和不可用能力均有明确文案。
- 账号 workspace 继续使用现有 revision/CAS。两个标签页冲突时保留未同步修改并要求重新加载或显式重试，不做静默 last-write-wins。
- 清点 notebook、selection、report draft 与 reader progress 的真实 owner；属于本版必须续用的笔记不能只停留在浏览器 localStorage。
- 精确续读绑定 paper/source revision；来源变化无法定位时提示变化并安全回到可用位置，不能假装定位成功。
- 桌面验收覆盖 1366×768、1920×1080、125% 缩放和键盘访问；主要操作无被遮挡控件，焦点、错误和异步状态可感知。

### D6：真实来源

- 搜索条件、来源类型和目标分组可见；原始请求在失败后可修改或重试，不能用 fixture 数据填充真实页面。
- arXiv/DOI/GitHub 走现有解析或搜索服务。GitHub 引用仅作为来源/项目材料，不执行仓库代码。
- PDF 接收沿用既有大小、类型、路径和 source policy 限制；重复点击、断连和重试保留导入身份，解析完成前不得伪造正文。
- 页面能区分未配置、网络不可达、来源拒绝、超时、解析失败、metadata-only 和已可阅读；可读结果必须具备既有发布/完整性证据。

### D7/D8：运行与报告

- 前端只能调用 BFF/API/application service，既有 Harness 继续决定预算、路由、验证、重试、写入和发布。
- 分析/问答的 source revision、问题和选中证据在提交时固定；服务端过滤用户可设置 options，不允许修改质量门、工具授权、实验开关或 publication policy。
- 分析、问答及有副作用的导入必须在首次发送前生成并按 owner 持久化稳定 request 标识及当前实例/恢复代际；服务端原子绑定 admission，支持按该标识查询，run/import 身份可随后返回。首次回执完全丢失、双击/超时/刷新后同一请求不能产生重复付费执行；同标识不同内容应拒绝。若既有实现不足，在其 application/persistence 边界补齐，禁止只靠按钮 disabled。
- 中断后能够核对 terminal result 与诊断；只在后端确认后显示已取消，纯浏览器 abort 只能称为停止等待。不新增通用队列或第二套调度器。
- 报告引用既有 Research run/artifact，显示来源、适用条件、质量状态、生成时间与修订。证据链接回到正确论文/章节/页码，损坏和过期来源有清楚提示。
- 保存报告是保存有 owner 的结果引用或用户草稿；不把候选文本写成已接受 artifact。Markdown/JSON 导出保持来源和质量语义并校验权限；用户草稿可独立导出但必须标明草稿。
- 渲染来自论文或模型的 Markdown/链接时按现有安全边界处理，不执行脚本，不把内部绝对路径或 provider 内容直接作为错误展示。

### D9：本机操作体验

提供 `doctor`、`build`、`start`、`stop`、`restart`、`status`、`logs`、`backup`、`restore`、`rollback` 与 `open`；每个动作有帮助文本、稳定退出码，机器结果支持 JSON。

`start` 幂等，后台运行且日志可查；只在实际健康后显示就绪。端口被无关程序占用时说明冲突，不能误杀或悄悄换 origin。`stop/restart` 只操作本工具确实拥有的进程；业务任务按既有生命周期收敛。默认不开机自启，可提供显式启用/关闭的当前用户登录启动选项。

### D10：数据与版本恢复

- 建立真实存储清单：账号、会话、workspace/history、论文导入、笔记/选区、Research 结果、原始/派生产物、必要 Harness events/checkpoints 与索引，以及恢复所需的非秘密配置身份。
- 首版采用受控停写/停服务的一致性备份；检测外部 writer 或无法建立一致性时失败，不复制半写 JSON 或仅复制 SQLite 主文件。
- 备份包含 manifest、schema/build、内容 checksum、包含/排除项。认证/私有内容受本机访问控制保护；默认不收集 provider 密钥、原始 `.env`、任意 prompt 日志、缓存、node_modules 或大模型。
- 会话记录在恢复后失效，要求重新登录。既有 admission owner 创建新恢复代际；恢复出的非终态/未知请求和旧标签页请求不得自动执行，查无记录不构成再次调用外部服务的许可。需要新执行时由用户明确创建新身份；历史 run/artifact 保持原身份只读可查。外置凭据须在恢复清单明确“需要重新提供”，不能显示为完全自包含备份。
- 恢复先在独立目录验证路径、完整性、schema、owner 与 artifact 引用；inventory 明确 owner 到恢复根的映射，不能安全重定位的持久化绝对引用须拒绝。校验用的 application 配置只能读取恢复目标，验收时使原业务数据根对校验进程不可访问；明确列出的外置依赖除外。拒绝越界/junction/symlink 和校验错误，切换失败时保留原数据及预恢复快照。
- 旧版本必须有可用的代码、构建、依赖身份；数据不兼容时拒绝原地降级，只允许使用兼容备份恢复。不得自动进行破坏性反向迁移。
